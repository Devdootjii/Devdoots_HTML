Introduction — Data Structure & ADT

Basic terminology · data organization · abstract data types

Socho tumhare ghar me alag-alag cheezein kahan rakhi hoti hain — kapde alamaari me, bartan kitchen me, books desk pe. Agar sab kuch ek bori me daal do, toh kuch bhi dhoondhne me ghanton lagenge. Data Structure bilkul yehi hai — data ko memory me aise organize karna jusse usse operations (insert karna, delete karna, search karna) efficient ho jayein. Sahi dhancha = kaam aasaan, galat dhancha = har operation me jhanjhat.

Kyun zaroori hai? Maan lo college me 10,000 students ka record hai. Bina kisi order ke rakha hua data ho toh kisi ek student ko dhoondhne ke liye har record check karna padega. Wahi data agar sorted array ya hash table me ho toh search seconds me ho jaayega. Program ki speed aur memory dono data structure ke choice pe depend karti hai — isliye yeh subject har CSE student ka core hai.

DEFINITION — EXAM ME AISA LIKHO

Data Structure: A data structure is a systematic way of organizing, storing and managing data in memory so that efficient operations can be performed on it. Data structures are classified as linear (array, linked list, stack, queue) and non-linear (tree, graph).

Basic Terminology — data ki hierarchy

Data ki poori hierarchy ek pyramid hai — yaad rakho: bit → field → record → file → database. Bit sabse chhoti unit (0 ya 1). Field ek logical unit jaise Roll_No, Name, Marks. Record ek entity ke saare related fields ka group — Divyansh ka record: (45, "Divyansh", 88). File same-type records ka collection, aur database multiple judii hui files. C me record struct se banta hai.

DATA KI HIERARCHY — PYRAMID
DATABASE
FILE — saare students ke records
RECORD — (Roll, Name, Marks) — ek student
FIELD — Roll_No · Name · Marks (ek property)
BIT — 0 / 1 (sabse chhoti unit)

Upar se neeche aate ho toh detail badhti jaati hai. Data item = single unit of data (jaise ek roll number). Entity = wo cheez jiske baare me data store karte ho (jaise ek student).

DATA vs INFORMATION

Data = raw, unprocessed facts — "88", "Divyansh". Akele koi matlab nahi.
Information = processed, meaningful data — "Divyansh top-3 me hai, 88 marks ke saath." Data + processing = Information. Exam me yeh 2-marker ready rakhna.

LINEAR vs NON-LINEAR

Linear: elements ek sequence me — ek ke baad ek (array, linked list, stack, queue).
Non-linear: hierarchy ya network — tree (parent-child), graph (koi bhi kisi se juda). Yeh classification 2-mark ka favourite hai.

BUILT-IN DATA TYPES IN C

Primary: int, float, char, double
Derived: array, pointer, function
User-defined: struct, union, enum
Data Structure in sab se banta hai — built-in nahi hota.

ELEMENTARY DATA ORGANIZATION

Memory me data rakhne ke do tareeke: contiguous (ek ke baad ek, bina gap — array) aur linked (kahin bhi scattered, pointers se juda — linked list). Pura course isi tension pe chalta hai!

ADT — Abstract Data Type

ADT ka core idea: "kya karna hai" (interface) ko "kaise karna hai" (implementation) se alag rakhna. TV ka remote lo — aap sirf jaante ho button dabao → channel change. Andar ka circuit kaise kaam karta hai, aapko farak nahi padta. Remote company kal andar ka circuit badal de, aapka remote dabane ka tareeka same rahega. Yehi abstraction hai — complexity chhupao, sirf zaroori cheez dikhao.

DEFINITION — EXAM ME AISA LIKHO

Abstract Data Type (ADT): An ADT is a mathematical model of a data structure that specifies what operations can be performed, but hides how they are implemented. It consists of (1) the data objects, (2) the set of operations (insert, delete, search, traverse), and (3) the interface — independent of any programming implementation.

Faayda: implementation badlo, user ka code nahi tootega. List ka ADT banao — operations insert(), delete(), search(). Ab ise array se banao ya linked list se — user ko farak hi nahi padta, wahi calls karta rahega. Stack aur Queue bhi pehle ADT hote hain, phir unki array + linked implementations aati hain — isi liye syllabus me har jagah "Array and Linked Implementation" likha hai.

// ADT ka idea C me aise dikhta hai:
typedef struct {
    insert(...);   // WHAT — interface
    delete(...);   // user ko bas yeh dikh raha hai
    search(...);
} ListADT;

// HOW — array implementation? linked list? user ko kya pata,
// user ko kya farak padta hai. Kal badal denge, kuch nahi tootega.

Arrays

1-D · 2-D · memory layout · row/column major · address formulae

Array socho ek train ke dabbey 🚂 — sab ek line me, sabka design same, har dabbe ka ek number. Wahi array hai: same-type elements, contiguous (bina gap) memory me, har element ka index. int marks[5] = 5 dabbon ki train jisme sirf int type ka data baith sakta hai.

DEFINITION — EXAM ME AISA LIKHO

Array: An array is a finite, ordered collection of elements of the same data type, stored in contiguous memory locations, accessed by an index. The base address is the address of the first element; each element occupies a fixed number of bytes called the word size (W).

Array ka superpower — O(1) direct access. Teesre dabbe me kya hai? Poori train chalna zaroori nahi — base pata hai, size pata hai, seedha jump maro. Isi se 1-D address formula banta hai: "us element tak jaane ke liye kitne elements paar karne padenge × size + base". C me lower bound L = 0 hota hai, par exam me kabhi 1-based ya custom bounds (jaise A[−10..50]) dete hain — tab full formula kaam aata hai.

Addr(A[i]) = B + W × (i − L) B = base address · W = word size (bytes) · L = lower bound · C me L = 0

2-D Arrays — Row Major vs Column Major ⭐

2-D array logically ek grid hai, par memory actually flat (ek line) hai — "real" 2-D memory hoti hi nahi. Toh grid ko line me kaise failaayen? Row Major: pehli poori row, phir dusri, phir teesri — bilkul jaise page padhte ho, line by line (C, C++, Python me yehi). Column Major: pehli poori column, phir dusri — Fortran, MATLAB style. Same array, do alag memory arrangement — isi liye address bhi alag aata hai.

Row Major = pehli poori row phir agli row · Column Major = pehli poori column phir agli column. Dono me element ki jagah alag — isliye address formula bhi alag.

Formula ratna nahi, sonchna hai. Row major me A[i][j] se pehle kitne elements? i poori rows (har row me N elements) + j elements apni row me. Column major me bas palat do — j poori columns (each of M) + i elements column me. Trick yaad rakho: jis order me store ho raha hai, usi me "poori" cheez aage count hoti hai — row major me N (columns) multiply hota hai, column major me M (rows).

ROW MAJOR:  Addr(A[i][j]) = B + W × [ i × N + j ] N = number of columns · M = number of rows · lower bound 0 maan kar
COLUMN MAJOR:  Addr(A[i][j]) = B + W × [ j × M + i ] 1-based ya custom bounds ho to i → (i − L₁), j → (j − L₂) kar do — bas!
3-D ROW MAJOR:  Addr(A[i][j][k]) = B + W × [ i × n₂n₃ + j × n₃ + k ] n₂, n₃ = dusri/teesri dimension ke sizes · pattern: har naya dimension ek multiply aur lagata hai
Guaranteed numerical: int A[10][20], base = 2000, W = 4, element A[3][5] dhoondo —
Row Major: 2000 + 4 × (3×20 + 5) = 2000 + 4×65 = 2260  ·  Column Major: 2000 + 4 × (5×10 + 3) = 2000 + 4×53 = 2212
Same element, alag order me alag jagah — isliye question me order mention hota hai.

Advantages & Limitations

✔ ARRAY KI TAAKAT
  • Random access O(1) — formula se seedha kisi bhi element pe jump
  • Memory friendly — sirf data, koi pointer ka overhead nahi
  • Cache friendly — contiguous hone ki wajah se CPU cache isse bahut pasand karta hai
  • Simple — 2-D arrays se matrices, tables sab ban jaate hain
  • Fixed size pe best — jaise calendar ke 12 months, 7 din
✘ ARRAY KI KAMZORI
  • Size fix — compile time pe decide; full ho gaya toh overflow, kam use hua toh memory waste
  • Insertion/deletion O(n) — beech me ghusao toh baad ke sab elements shift karne padte hain
  • Reallocation me pura data copy karna padta hai
  • Same type only — mixed data ke liye struct chahiye
  • Ye dono problems Linked List solve karta hai (section 03)

Sparse Matrices

Zyada tar zero · triple representation · memory savings

"Sparse" matlab bikhra hua / patla. Sparse matrix wo hai jisme zyada tar elements zero hain. Socho 1000×1000 ki matrix me sirf 10 numbers kaam ke hain — toh baaki 9,99,990 zeros ko memory me rakhne ka kya faayda? Zeros store karna memory ki barbadi hai. Solution: sirf non-zero elements store karo, unke saath teen cheezein — kaunsi row, kaunsi column, value kitni. Isi triple (row, col, value) format me store karte hain.

DEFINITION — EXAM ME AISA LIKHO

Sparse Matrix: A matrix in which the number of zero elements is much larger than the number of non-zero elements. To save memory, only the non-zero elements are stored as triples (row, column, value), along with a header entry (total rows, total columns, number of non-zero elements).

Hisaab dekho — 1000×1000 matrix, int = 4 bytes. Dense: 10,00,000 × 4 = 40 lakh bytes. Sparse: sirf (10 non-zero + 1 header) × 3 values × 4 = 132 bytes. Transpose ka smart trick: triples ko column-major order me scan karo (col 0 ke saare, phir col 1 ke...), jisse mile usme row↔col swap karke naye list me daalo — result automatically sorted, bina alag se sorting ke.

Linked Lists

Node structure · singly / doubly / circular · insert · delete · traverse

Array ki dono badi problems ka solution: size dynamic aur insertion/deletion me shifting nahi — sirf pointers badlo. Elements memory me kahin bhi scattered rehte hain, pointers se ek chain me jude. Har node ke 2 hisse: DATA (asli value) + NEXT (agla pata). Train me har dabba fixed tha; yahan har dabba kahin bhi hai, bas har dabbe me agle dabbe ka address likha hai. Pehle node ko head kehte hain, last node ka next = NULL.

struct Node {
    int data;              // asli value
    struct Node *next;     // agle node ka address
};

// naya node banana (dynamic — jitne chahiye, runtime pe):
struct Node *newNode = (struct Node*) malloc(sizeof(struct Node));
newNode->data = 25;
newNode->next = NULL;

Operations — Insert · Delete · Traverse

INSERT @ BEGINNING — O(1)

Naya node banao → uska next = head → head = naya node. Bas teen lines, koi shifting nahi. Array me yeh kaam O(n) tha!

INSERT @ END — O(n)

Last node tak travel karo (temp = temp->next loop) → temp->next = naya node. End tak jaana padta hai isliye O(n).

INSERT @ POSITION P — O(n)

P−1 tak jao → naye node ka next = current ka next → current ka next = naya node. Link pehle jodo, phir todo — order ulta kiya toh list kho jayegi!

DELETE — O(n)

Target ke pehle node tak jao → uska next target ke next pe point karwa do → free(target). Head delete ho raha ho toh head = head->next.

TRAVERSE — O(n)

temp = head se shuru, jab tak temp != NULL, data print karte jao aur aage badho. Yehi list ka "padhna" hai.

SEARCH — O(n)

Traverse karte karte har node ka data compare karo. Mil gaya toh return index/wahi node. Best case pehla node Ω(1), worst O(n).

Syllabus me array implementation bhi hai — nodes ek struct array me, index se linked (free list maintain karni padti hai) — aur pointer implementation jo practical hai (malloc/heap). Ab teen variants: Singly — ek hi direction, sirf next. Doubly — har node me prev + next dono; dono taraf travel, delete easy, par extra pointer = extra memory (2 pointers per node). Circular — last node wapas head ko point karta hai; NULL khatam; round-robin scheduling (CPU time-sharing) me use.

Stacks

LIFO · push / pop / peek · array + linked implementation · applications

Stack ka rule ek hi hai — LIFO: Last In, First Out. Canteen me plates ka dher 🍽️ — nayi plate upar rakhi jaati hai, aur sabse upar wali plate hi pehle uthaayi jaati hai. Beech se ya neeche se koi plate nahi nikal sakta. Stack me bhi sirf ek taraf se daalo aur usi taraf se nikaalo — us jagah ka naam TOP. Jo aakhri me gaya, wo pehle bahar aayega — bas, yahi poori kahani hai.

DEFINITION — EXAM ME AISA LIKHO

Stack: A stack is a linear data structure in which insertion and deletion are allowed only at one end, called the top. It follows the LIFO (Last-In-First-Out) principle. Primitive operations: push (insert at top), pop (remove from top), peek/top (read top without removing). Overflow = push on full stack; Underflow = pop/peek on empty stack.

Push order: 10, 20, 30, 40
Pop order: 40, 30, 20, 10 — ulta! LIFO 🎯 
// Array implementation — top = index of latest element
int stack[MAX], top = -1;              // -1 = empty

void push(int x) {
    if (top == MAX-1) printf("Overflow!");   // full
    else stack[++top] = x;                   // O(1)
}
int pop() {
    if (top == -1) printf("Underflow!");    // empty
    else return stack[top--];                 // O(1)
}

Linked implementation: push = insert at head, pop = delete from head — dono O(1), aur size dynamic (overflow ka tension khatam). Applications (exam ke liye 5 yaad rakho): recursion ka function call stack, expression evaluation (postfix/prefix conversion — Unit II me detail), undo (Ctrl+Z har app me), browser back button, aur DFS graph traversal. Undo ka logic samjho: har action stack me push hota hai, Ctrl+Z = pop = last action wapas ultiya!

05

Queues

FIFO · enqueue / dequeue · circular · dequeue (DQ) · priority · applications

Queue ka rule — FIFO: First In, First Out. Ticket counter ki line 🎫: jo pehle aaya wahi pehle ticket lega, naye log peeche lagte hain. Isliye queue me insertion REAR se aur deletion FRONT se hota hai — do pointers chahiye (front, rear), stack me sirf top kaafi tha.

DEFINITION — EXAM ME AISA LIKHO

Queue: A queue is a linear data structure in which insertion is allowed only at the rear and deletion only at the front, following the FIFO (First-In-First-Out) principle. Operations: enqueue (add at rear), dequeue (remove from front), isEmpty, isFull. A circular queue connects the last position back to the first so freed space can be reused.

Simple array queue ki problem: front se elements nikalne ke baad aage ki slots khaali reh jaati hain, par rear aage badh chuka hota hai — queue "full" dikhta hai jabki jagah waste padi hai. Solution = Circular Queue: array ko gol maan lo, indices (i + 1) % size se wrap ho jaate hain. Rear last tak pahunch ke wapas index 0 pe aa jaata hai. Full memory reuse, koi waste nahi.

DEQUEUE (Double-Ended)

Dono ends se insert + delete dono allowed — 4 operations: insertFront, insertRear, deleteFront, deleteRear. Use: browser history (dono taraf scroll), undo-redo dono.

PRIORITY QUEUE

Har element ke saath priority number. High priority pehle niklega, chahe baad me aaya ho. Hospital emergency me pehla aaya nahi — sabse serious patient pehle! OS process scheduling ka core.

APPLICATIONS

Printer spooling (documents line me print), CPU scheduling (ready queue round-robin), keyboard buffer, call-center hold line, BFS graph traversal. Sab jagah "line me lag jao" = queue.

Time Complexity — Asymptotic Notations

Big Oh · Big Omega · Big Theta · time-space trade-off

Do algorithms dono sahi answer de rahe hain — better kaun? Jo kam time/memory le. Par seconds me naapa nahi jaata (fast laptop vs purana PC alag time dikhate hain). Isliye hum step count karte hain — input size n ke function me. 3 golden rules: constants drop (3n+5 → n), lower-order terms drop (n² + 100n → n²), sirf dominant term rakho. Growth dekho, exact numbers nahi.

BIG O — UPPER BOUND

"Zyada se zyada itna hi hoga" — worst case ki guarantee. 3n + 5 ≤ 4n for n ≥ 5, toh 3n+5 = O(n). Exam: definition + c, n₀ wala inequality likhna.

BIG Ω — LOWER BOUND

"Kam se kam itna toh hoga hi" — best case. Linear search me key pehli jagah mile toh Ω(1), nahi toh Ω(n) se kam nahi.

BIG Θ — TIGHT BOUND

"Isi range me rahega" — dono taraf se sandwiched. f(n) O(g) bhi ho aur Ω(g) bhi, toh Θ(g). Exact order.

DEFINITION — EXAM ME AISA LIKHO

Big-O: f(n) = O(g(n)) if there exist positive constants c and n₀ such that f(n) ≤ c·g(n) for all n ≥ n₀.  ·  Big-Ω: f(n) ≥ c·g(n) for all n ≥ n₀.  ·  Big-Θ: c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀.

Growth ladder yaad kar lo: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ). O(1) = input kitna bhi ho time same (array access). O(log n) superfast — 1 crore elements me binary search ~24 steps. O(n²) = danger — input 10× hua toh time 100×! Aur Time-Space Trade-off: time bachana ho toh memory kharch karo (lookup tables, hash maps), memory bachani ho toh time kharch karo (recompute) — dono ek saath minimum nahi ho sakte, balance chunna padta hai.

Q&A — Expected Exam Questions

Question kholo, khud answer likho, phir model answer se check karo

Define data structure. Classify linear and non-linear data structures with examples. 2 MARKS

A data structure is a systematic way of organizing, storing and managing data in memory so that efficient operations (insertion, deletion, searching, traversal) can be performed on it.

Linear: elements in a sequence, each having one predecessor and one successor — array, linked list, stack, queue. Non-linear: elements arranged in hierarchy or network — tree (parent-child), graph (nodes connected arbitrarily).

What is an Abstract Data Type (ADT)? Give an example. 2 MARKS

An ADT is a mathematical model of a data structure that specifies what operations can be performed and what they do, while hiding how they are implemented. It separates specification (interface) from implementation.

Example: a List ADT offers insert, delete and search operations; it can be implemented using either an array or a linked list without changing the way the user calls the operations. Stack and Queue are also ADTs with array-based and linked implementations.

An array A[10][20] is stored in row-major order with base address 2000 and each element of 4 bytes. Calculate the address of A[3][5]. Also compute it for column-major order. 5 MARKS

Given: M = 10 rows, N = 20 columns, B = 2000, W = 4, element A[3][5] (0-based).

Row Major: Addr = B + W × (i × N + j) = 2000 + 4 × (3 × 20 + 5) = 2000 + 4 × 65 = 2000 + 260 = 2260

Column Major: Addr = B + W × (j × M + i) = 2000 + 4 × (5 × 10 + 3) = 2000 + 4 × 53 = 2000 + 212 = 2212

Conclusion: the same element occupies a different address under the two storage orders — that is why the question always specifies the order.

What is a sparse matrix? Explain its triplet (row, column, value) representation with an example. 5 MARKS

A sparse matrix is a matrix in which the number of zero elements greatly exceeds the non-zero elements. Storing the zeros wastes memory, so only non-zero elements are stored as triples (row, col, value) with a header row (total rows, total columns, count of non-zero entries).

Example: a 1000×1000 matrix with only 10 non-zero elements needs 1000×1000×4 = 4,000,000 bytes if stored densely, but only (10+1)×3×4 = 132 bytes in triplet form. Triples are kept sorted in row-major order so that operations (transpose, addition) remain predictable.

Compare arrays and linked lists — memory, access, insertion/deletion, size, applications. 10 MARKS

Memory: array is contiguous; linked list nodes are scattered and carry pointer overhead. Access: array O(1) random access by index formula; linked list O(n) sequential access from head. Insertion/deletion: array needs O(n) shifting of elements; linked list needs only pointer changes (O(1) at head, O(n) only to reach the position). Size: array fixed at compile time; linked list grows/shrinks at runtime via malloc/free. Cache behaviour: arrays are cache-friendly; linked lists are not.

When to use: arrays when reads dominate and size is known (lookup tables, matrices); linked lists when insertions/deletions dominate or size is unpredictable. A 10-mark answer should include the node structure diagram and one example operation (insert at beginning) for both.

Explain stack and queue operations with their real-life applications. Write push/pop algorithms. 10 MARKS

Stack (LIFO): single-ended structure — push inserts at top, pop removes from top, peek reads the top. Overflow on push-full, underflow on pop-empty. Applications: function call stack in recursion, postfix/prefix expression evaluation, undo, browser back, DFS.

Queue (FIFO): insert at rear (enqueue), delete at front (dequeue). Applications: printer spooling, CPU scheduling (round-robin), keyboard buffer, BFS. Circular queue reuses freed front slots via (i+1) % size indexing.

Write the array push/pop code from section 04 — with top = −1 initialisation and both boundary checks — full marks.

09

Exam Corner

Saari verbatim definitions ek jaghah + last-minute 15 one-liners

DATA STRUCTURE

A systematic way of organizing, storing and managing data in memory so that efficient operations can be performed on it. Classified as linear and non-linear.

ADT

A mathematical model specifying what operations a data structure supports, independent of implementation — consists of data objects, operations, and interface.

ARRAY

A finite, ordered collection of elements of the same data type stored in contiguous memory locations, accessed by index. Base address = address of first element.

ROW MAJOR ORDER

2-D array storage where the entire first row is stored first, then the second row, and so on. C and C++ use row-major. Addr(A[i][j]) = B + W×(i×N + j).

COLUMN MAJOR ORDER

2-D array storage where the entire first column is stored first, then the second column. Fortran uses it. Addr(A[i][j]) = B + W×(j×M + i).

SPARSE MATRIX

A matrix in which most elements are zero; stored economically as triples (row, column, value) of non-zero elements with a header row (rows, cols, count).

LINKED LIST

A linear data structure of nodes, each holding data and a pointer to the next node; nodes occupy non-contiguous memory and the list is accessed via the head pointer.

STACK

A linear structure where insertion and deletion occur only at one end (top), following LIFO. Operations: push, pop, peek. Errors: overflow, underflow.

QUEUE

A linear structure where insertion occurs at the rear and deletion at the front, following FIFO. Circular queue uses (i+1) % size to reuse space.

TIME COMPLEXITY

The amount of computation an algorithm performs as a function of input size n, expressed via asymptotic notation independent of machine speed.

BIG-O NOTATION

f(n) = O(g(n)) if ∃ constants c > 0, n₀ such that f(n) ≤ c·g(n) for all n ≥ n₀ — the asymptotic upper bound (worst case).

TIME-SPACE TRADE-OFF

Reducing time requires additional memory and vice-versa; one cannot minimise both simultaneously — a balance is chosen per application.

  1. bit → field → record → file → database — yehi hierarchy hai.
  2. Data + processing = information.
  3. C me array index hamesha 0 se, aur row-major store hota hai.
  4. 1-D: B + W×(i−L) — lower bound na bhoolo!
  5. Row major me N (columns) multiply hota hai; column major me M (rows).
  6. 3-D me bas ek aur term: i×n₂n₃ + j×n₃ + k.
  7. Sparse triple ka header: (total rows, total cols, non-zero count).
  8. Linked list node = DATA + NEXT; last node ka next = NULL.
