#include <stdio.h>

int main() {
    int a[5] = {10, 20, 30, 40, 50};   // array — 5 values ek jagah
    int i, sum = 0;                     // sum ko 0 se shuru kiya

    for (i = 0; i < 5; i++) {           // i = 0,1,2,3,4 (5 nahi!)
        sum = sum + a[i];               // sum me a[i] jodo
    }

    printf("Sum = %d\n", sum);           // 150
    return 0;
}

Is program ko samajhne ka best tareeka — ise step by step chalao. Isi ko dry run kehte hain, aur yeh skill exam me aur sorting ke trace me sabse zyada kaam aayegi. Neeche tracer me STEP dabao aur dekho i aur sum kaise badalte hain:

Function me array bhejna

Ab sabse zaroori C concept — function. Function = ek kaam ka packet, jise naam de kar baar-baar bula sakte ho. Unit 3 me har algorithm ek function hi hoga: linearSearch(a, n, key), bubbleSort(a, n). Do baatein yaad rakho: 1. Array apna size saath nahi laata — isliye n (elements ki count) alag se bhejni padti hai 2. Array by reference jata hai — function ke andar jo bhi change karoge (jaise sort), wo bahar bhi dikhega. Isliye bubbleSort(a, n) call karne ke baad a sorted milta hai.

/* function definition — array + size + jo dhoondhna hai */
int linearSearch(int a[], int n, int key) {
    int i;
    for (i = 0; i < n; i++) {
        if (a[i] == key)
            return i;        // mila → index wapas
    }
    return -1;               // nahi mila → -1
}

int main() {
    int a[5] = {10, 25, 30, 45, 60};
    int pos = linearSearch(a, 5, 45);   // function CALL
    printf("Mila index %d pe\n", pos);   // 3
    return 0;
}
Dekha? Yeh Unit 3 ka pehla topic hai! Linear search bas loop + array + function + if ka mel hai — koi nayi cheez nahi. Isliye Unit 3 itna darawna nahi hai jitna lagta hai: 90% cheezein yahi teen chaar building blocks se banti hain.

Swap aur Shifting — sorting ki jaan

Swap — do values ki jagah badalni ho toh temp chahiye. Seedha a = b karne se a ki purani value kho jayegi. Sahi tareeka:

temp = a;
a = b;
b = temp;

Yeh teen lines bubble, selection aur quick sort me har swap pe repeat hongi. Aur shifting — insertion sort me hota hai: ek jagah khaali karne ke liye baaki elements ko ek-ek kadam aage sarakna padta hai. Dono cheezein neeche live dekho:

⚡ ARRAY PLAYGROUND— swap aur shifting live karke dekho
Do index daalo aur SWAP dabao — dekho temp variable ke bina kya hota. SHIFT se insertion sort ka movement dikhega.

SWAP — SORTING KA HEARTBEAT

Bubble sort: adjacent swap. Selection sort: minimum ko aage laane ke liye swap. Quick sort: partition me swap. Insertion sort me swap ki jagah shift hota hai — elements ek kadam aage sarakte hain.

ARRAY MEMORY — O(1) ACCESS

Array ka base address pata ho aur size pata ho, toh kisi bhi element ka address formula se nikal jata hai: Addr(a[i]) = base + i × size. Isliye a[3] dekhna O(1) hai — chahe array 5 ka ho ya 5 lakh ka. Binary search isi pe khadi hai.

Recursion — Sabse Zaroori Topic

Function khud ko call kare · base case · call stack · merge & quick ke liye

Recursion = function khud ko call kare. Socho tum kisi se poocho "yeh kaam kar do", aur wo aage kisi aur se wahi kaam pooch le — chain chalti rehti hai jab tak sabse chhota case na aa jaye. Recursion me do cheezein hamesha chahiye: 1. Base case — rukne ki shart (jahan function khud ko call na kare, seedha answer de de) 2. Recursive case — khud ko chhote input ke saath call karna Base case nahi hoga toh function kabhi nahi rukega → stack overflow → program crash. Yeh sabse common galti hai.

DEFINITION — EXAM ME AISA LIKHO

Recursion: A programming technique in which a function calls itself to solve a smaller instance of the same problem. Every recursive function must have a base case (terminating condition) and a recursive case that moves toward the base case. Recursion uses the system's call stack to store pending calls.

Example: Factorial (n!)

Factorial (n!) sabse aasan example hai. 4! = 4 × 3 × 2 × 1. Recursion se likho toh: 4! = 4 × 3! → 3! = 3 × 2! → 2! = 2 × 1! → 1! = 1 ← base case! Dekho har baar input ek kam ho raha hai — isliye function base case tak zaroor pahunchega. C code:

int factorial(int n) {
    if (n == 1 || n == 0)     // BASE CASE — yahan ruk jao
        return 1;

    return n * factorial(n - 1);   // RECURSIVE CASE — khud ko bulao
}

int main() {
    printf("%d", factorial(4));   // 24
    return 0;
}

Ab sabse zaroori baat: jab function khud ko call karta hai, har call call stack me jama hoti jaati hai. Jab tak base case nahi milta, upar wali calls apna kaam adhoora chhod kar intezaar karti hain. Base case ka answer milte hi stack ulta khali hone lagta hai (LIFO — jo last me gaya, wo pehle wapas) aur har call apna multiply karke jawab upar bhej deti hai. Neeche stepper me poora khel chalta hua dekho:

⚠ COMMON GALTIYAN

1. Base case bhoolna → infinite recursion → stack overflow (program crash).
2. Input chhota na karna — jaise factorial(n) ke andar factorial(n) likhna. Har call me n−1 jaisa kuch hona chahiye.
3. Return bhoolna — recursive call ka result use karna zaroori hai.

UNIT 3 ME RECURSION KAHAN?

Merge sort: array ko aadha todta hai, phir dono halves pe khud ko call karta hai — classic recursion.
Quick sort: partition ke baad left aur right pe khud ko call.
Heap sort: heapify khud ko call karta hai.
Isliye recursion samajh gaye toh Unit 3 ka aadha kaam aasaan ho gaya!

RECURSION vs ITERATION

Iteration (loop): code chhota, memory kam, fast. Recursion: code saaf aur chhota dikhta hai, par har call stack me jagah leti hai (space O(n)). Merge/quick sort recursion se bahut natural lagte hain — isliye wahan recursion use hota hai.

FIBONACCI — DO RECURSIVE CALLS

fib(n) = fib(n-1) + fib(n-2), base: fib(0)=0, fib(1)=1.
Yahan ek function do baar khud ko call karta hai — isse tree jaisa branching banta hai. Isi liye plain recursive Fibonacci slow hota hai (O(2ⁿ)) — memoization se tez karte hain.

Board pe yeh likhna (dry run): factorial(4) ka trace — 4×fact(3) → 3×fact(2) → 2×fact(1) → 1, phir wapas aate hue 2×1=2 → 3×2=6 → 4×6=24. Exam me aise hi likhna hai: pehle jaate hue (calls), phir aate hue (returns).

Big-O — Kaun Tez, Kaun Slow

Complexity ka basic idea — Unit 3 ka poora comparison isi pe khada hai

Unit 3 me har sorting algorithm ki tulna hoti hai, aur woh tulna time complexity se hoti hai. Socho do dost ek hi kaam kar rahe hain — ek ko 2 ghante lage, dusre ko 2 din. Dono ka jawab sahi, par better wahi jo tez hai. Algorithm me hum asli seconds nahi naapte (woh computer pe depend karta hai) — hum dekhte hain ki input ka size badhne pe kaam kitna badhta hai. Isi ko Big-O kehte hain. Bas itna hi basic chahiye Unit 3 ke liye.

DEFINITION — EXAM ME AISA LIKHO

Time Complexity: The amount of computation an algorithm performs as a function of the input size n, expressed using asymptotic notation (Big-O). Big-O gives the upper bound — the worst-case growth rate. Example: O(n) means the work grows proportionally with n; O(n²) means it grows with the square of n.

O(1) — CONSTANT

Input kitna bhi bada ho, kaam same. Jaise array me a[3] dekhna — seedha jump, koi loop nahi.

O(log n) — LOGARITHMIC

Har step me kaam aadha ho jata hai. Jaise dictionary me shabd dhoondhna. 1000 elements me sirf ~10 steps. Binary search iska star example hai.

O(n) — LINEAR

Ek-ek element dekhna padta hai. Input double → kaam double. Jaise linear search.

O(n²) — QUADRATIC

Nested loop. Input 10× → kaam 100×! Bubble, selection, insertion sort isi family me hain. Isliye bade data pe yeh slow padte hain.

O(n log n) — FAST SORTS

Merge, quick (average) aur heap sort. Yahi "achha" sorting hai — bade data pe O(n²) se bahut aage nikal jata hai.

LADDER YAAD RAKHO

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
Left = tez, right = slow. Unit 3 me har algorithm ko is ladder pe rakhna hai — bas.

Ab ise apni aankhon se dekho. Slider se input size badlo aur dekho — n² kitni tezi se bhaagta hai, jabki log n lagbhag ruka hua rehta hai. Yahi wajah hai ki binary search aur merge sort bade data pe itne powerful ho jaate hain:

⚡ GROWTH VISUALIZER— n badhao, dekho kaun kitna bhaagta hai
Unit 3 me kaise kaam aayega: sorting comparison me tumhe likhna hoga — bubble O(n²), merge O(n log n), quick average O(n log n) par worst O(n²). Isi ladder se yeh sab decide hota hai. Aur "1000 elements me binary search sirf 10 steps leta hai" — woh bhi O(log n) ki wajah se.

  • Sorted array mandatory
  • Worst case: O(log n) — 1000 me ~10 steps
  • Bade sorted data ke liye behtareen
Ab tum Unit 3 ke liye taiyaar ho! Linear search = loop + array + function (section 02). Binary search = + sorted array (section 05) + mid calculation. Hashing = + modulo (section 02 ka array). Bubble/selection/insertion = + swap (section 02). Merge/quick/heap = + recursion (section 03). Complexity table = section 04. Bas itna hi tha!
🧑‍🏫 Samjhane ka script — Sorted vs Unsorted + Searching
Yahin se Unit 3 officially shuru hota hai — isliye yeh block board pe karna.
Analogy

Unsorted list = bikhri hui kitabein — ek dhoondhne ke liye sab dekhni padegi. Sorted = library ki shelf — naam ke order me lagi hain, toh beech me dekh ke pata chal jata hai ki aage dhoondhna hai ya peeche. Phone ke Contacts me bhi tum letter pe jump karte ho — wahi idea hai.

Core idea (ek line)

Sorted data me tum aadha hissa ek hi baar me hata sakte ho — isi liye binary search O(log n) hai. Unsorted me ek-ek dekhna padta hai — linear search O(n).

Board pe kya likho (dry run — yeh exam me bhi aayega)
  1. Array likho: 3, 9, 12, 18, 23, 31, 40, 47, 56, 60 aur target = 47
  2. Table banao — column: low, mid, high, A[mid], decision
  3. Har step me hissa kaat do (kaatne wala hissa cross kar do) — students ko dikhega ki area kaise aadha hota ja raha hai
  4. Neeche likho: linear = 8 comparisons, binary = 3 comparisons
Common galtiyan
  • Unsorted array pe binary search lagana — yeh kaam hi nahi karta
  • mid = (low + high) / 2 me integer division bhoolna (C me 5/2 = 2 hota hai, 2.5 nahi)
  • Comparison ke baad low/high update galat karna — A[mid] < key ho toh low = mid + 1
  • Loop ki shart bhoolna — while (low <= high), warna infinite loop

"Ek list hai jisme numbers order me lage hain. Mujhe 47 dhoondhna hai. Main ek-ek nahi dekhunga — main beech wala dekhta hoon. Beech me hai 23 — 47 bada hai, toh 23 se pehle wala poora hissa khatam! Dekho, aadha array ek hi sawaal me gaya. Phir bache hue ka beech... tum batao, ab kitne elements bache?"

Program 9 (bubble sort) ka solution — Unit 3 ka pehla sorting program SOLUTION 
/* BUBBLE SORT — yeh Unit 3 ka pehla sorting topic hai! */
#include <stdio.h>
int main() {
    int a[7] = {29, 10, 14, 37, 13, 25, 8};
    int n = 7, i, j, temp;

    for (i = 0; i < n - 1; i++) {           // n-1 passes
        for (j = 0; j < n - 1 - i; j++) {   // adjacent compare
            if (a[j] > a[j + 1]) {          // galat order
                temp = a[j];                // swap
                a[j] = a[j + 1];
                a[j + 1] = temp;
            }
        }
    }

    for (i = 0; i < n; i++) printf("%d ", a[i]);
    return 0;
}
/* Output: 8 10 13 14 25 29 37 */
