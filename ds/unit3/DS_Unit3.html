Searching — dhoondhne ke 3 tareeke

Linear · Index Sequential · Binary Search

Searching = list me ek khaas element (key) dhoondhna aur batana ki kis index pe mila. Teen tareeke hain: - Linear search — ek-ek karke compare (unsorted pe bhi chalta hai, par O(n)) - Index sequential search — index table + blocks (bade sorted files ke liye) - Binary search — aadha-aadha kaat ke (sorted hona zaroori, par O(log n))

DEFINITION — EXAM ME AISA LIKHO

Searching: The process of locating a given element (key) in a collection, returning its position or reporting absence. Linear (sequential) search compares the key with each element one by one — works on unsorted data, worst case O(n). Binary search repeatedly halves a sorted array by comparing with the middle element — O(log n).

Linear search ka code — ek loop, ek condition, mila toh index warna −1:

/* SEQUENTIAL (LINEAR) SEARCH — C program */
#include <stdio.h>

int linearSearch(int a[], int n, int key) {
    int i;
    for (i = 0; i < n; i++) {
        if (a[i] == key)              // mil gaya
            return i;                 // index return karo
    }
    return -1;                        // nahi mila
}

int main() {
    int a[100], n, i, key, pos;
    printf("Enter number of elements: ");
    scanf("%d", &n);
    printf("Enter %d elements: ", n);
    for (i = 0; i < n; i++) scanf("%d", &a[i]);

    printf("Enter key to search: ");
    scanf("%d", &key);

    pos = linearSearch(a, n, key);
    if (pos == -1) printf("Element not found\n");
    else           printf("Element found at index %d\n", pos);
    return 0;
}

Binary Search — dictionary me shabd dhoondhne jaisa: beech me kholo, key chhoti hai ya badi dekho, aadha hissa hata do. Har step me area aadha — isliye 1000 elements me sirf ~10 steps.

/* BINARY SEARCH (iterative) — C program. Array SORTED hona chahiye! */
#include <stdio.h>

int binarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1, mid;

    while (low <= high) {
        mid = (low + high) / 2;        // beech ka index

        if (a[mid] == key)
            return mid;                // mil gaya
        else if (a[mid] < key)
            low = mid + 1;             // right half me dhoondo
        else
            high = mid - 1;            // left half me dhoondo
    }
    return -1;                        // nahi mila
}

int main() {
    int a[100], n, i, key, pos;
    printf("Enter number of elements: ");
    scanf("%d", &n);
    printf("Enter %d elements in SORTED order: ", n);
    for (i = 0; i < n; i++) scanf("%d", &a[i]);

    printf("Enter key to search: ");
    scanf("%d", &key);

    pos = binarySearch(a, n, key);
    if (pos == -1) printf("Element not found\n");
    else           printf("Element found at index %d\n", pos);
    return 0;
}
T(n) = T(n/2) + 1  ⇒  O(log₂ n) 1000 elements → ~10 comparisons · 10,00,000 elements → ~20 comparisons. Linear search me wahi data → 5,00,000 comparisons!
🧠 Yaad rakhne ka tareeka
  • Linear = ek-ek kholo (almari ke saare dabbe) · Binary = aadha kaato (dictionary)
  • Binary ke liye SORTED likhna mat bhoolna — exam me yahi check hota hai
  • Formula yaad rakho: mid = (low + high) / 2 · mila toh ruk jao, chhota hai toh low = mid + 1, bada hai toh high = mid − 1

Hashing — bina compare, seedha pata

Hash function · collision · chaining · open addressing · load factor

Hashing me hum compare nahi karte — formula lagakar seedha pata kar lete hain ki element kahan hai. Jaise class me har student ki tay seat. Formula: h(k) = k mod m (key ko table size se divide karo, remainder = index). Average search O(1).

DEFINITION — EXAM ME AISA LIKHO

Hashing: A technique of mapping keys to positions in a hash table using a hash function h(k), giving near-constant-time insertion, deletion and search. A collision occurs when two different keys map to the same index — resolved by chaining (linked list per slot) or open addressing (linear/quadratic probing, double hashing). Load factor α = n/m.

HASH FUNCTION METHODS

Division: h(k) = k mod m (sabse common)
Mid-Square: k² karo, beech ke digits — 23² = 529 → 52
Folding: tukdon me todo, jodo — 123456 → 12+34+56
Multiplication: ⌊m × (k×A mod 1)⌋, A ≈ 0.618

COLLISION — HAMESHA POSSIBLE

h(23) = 3 aur h(33) = 3 — same slot! Keys infinite, table finite — isliye collision rok nahi sakte, sirf resolve karte hain. Do families: chaining aur open addressing.

Chaining — har slot me linked list; colliding keys us list me chali jaati hain (table kabhi full nahi hota, par pointers ki extra memory). Open addressing — table ke andar hi agli khaali jagah dhoondho: linear probing (h + i), quadratic probing (h + i²), double hashing (h + i·h₂) — sabse best, clustering lagbhag khatam. Deletion me tombstone marker zaroori hai warna probe chain toot jayegi.

⚡ HASH BUCKETS— insert hote hue dekho, collision flash ke saath
LOAD FACTOR α = 0.00
Keys daalo aur INSERT dabao — collision wale slots coral ho jayenge.
🧠 Yaad rakhne ka tareeka
  • h(k) = k mod m — bas yeh ek line yaad rakho, poora hashing isi pe khada hai
  • Chaining = list per slot · Open addressing = andar hi adjust
  • Load factor α = n/m, ideal 0.5–0.75 · α > 1 ho gaya toh rehashing
  • Average O(1), worst O(n) (jab sab keys ek hi slot pe)
02

Sorting — BSI family (O(n²))

Bubble · Selection · Insertion — C program + dry run dono

Sorting = elements ko order me lagana. Teen simple algorithms — Bubble, Selection, Insertion (yaad rakho: B-S-I). Teeno O(n²) hain, par seekhne ke liye aur exam ke liye sabse zaroori.

Bubble Sort 🫧

Adjacent elements compare karo, galat order me ho toh swap. Har pass me sabse bada element bubble karke end me pahunch jata hai.

/* BUBBLE SORT — C program */
#include <stdio.h>
int main() {
    int a[100], n, i, j, temp;
    printf("Enter number of elements: ");
    scanf("%d", &n);
    printf("Enter %d elements: ", n);
    for (i = 0; i < n; i++) scanf("%d", &a[i]);

    for (i = 0; i < n - 1; i++) {          // n-1 passes
        for (j = 0; j < n - 1 - i; j++) {  // last i elements sorted hain
            if (a[j] > a[j + 1]) {          // galat order
                temp = a[j];                // swap
                a[j] = a[j + 1];
                a[j + 1] = temp;
            }
        }
    }
    printf("Sorted array: ");
    for (i = 0; i < n; i++) printf("%d ", a[i]);
    return 0;
}

pass 1: 1 4 2 5 8 ← 8 settle pass 2: 1 2 4 5 8 pass 3: 1 2 4 5 8 pass 4: 1 2 4 5 8 ✔ sorted

Best O(n) (sorted + flag ho toh), average/worst O(n²) · space O(1) · stable ✔

Selection Sort 🎯

Har pass me unsorted hisse se sabse chhota element dhoondho aur us pass ki pehli position pe swap kar do. Khaas baat: minimum swaps (n−1).

/* SELECTION SORT — C program */
#include <stdio.h>
int main() {
    int a[100], n, i, j, min, temp;
    printf("Enter number of elements: ");
    scanf("%d", &n);
    printf("Enter %d elements: ", n);
    for (i = 0; i < n; i++) scanf("%d", &a[i]);

    for (i = 0; i < n - 1; i++) {
        min = i;                        // maan lo yahi minimum hai
        for (j = i + 1; j < n; j++) {
            if (a[j] < a[min])          // chhota mila
                min = j;                // uska index yaad rakho
        }
        if (min != i) {                // minimum ko aage bhejo
            temp = a[i]; a[i] = a[min]; a[min] = temp;
        }
    }
    printf("Sorted array: ");
    for (i = 0; i < n; i++) printf("%d ", a[i]);
    return 0;
}

Har case me O(n²) (best me bhi poora scan) · space O(1) · unstable ✕ · swaps minimum

Insertion Sort 🃏

Taash ke patte jaisa: har naya card uthao aur sahi jagah pe insert kar do (bade cards ek-ek shift karke). Nearly-sorted data pe best case O(n).

/* INSERTION SORT — C program */
#include <stdio.h>
int main() {
    int a[100], n, i, j, key;
    printf("Enter number of elements: ");
    scanf("%d", &n);
    printf("Enter %d elements: ", n);
    for (i = 0; i < n; i++) scanf("%d", &a[i]);

    for (i = 1; i < n; i++) {
        key = a[i];                     // yeh card uthaya
        j = i - 1;
        while (j >= 0 && a[j] > key) {  // bade elements aage shift
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;                 // key sahi jagah pe
    }
    printf("Sorted array: ");
    for (i = 0; i < n; i++) printf("%d ", a[i]);
    return 0;
}
DRY RUN — [12, 11, 13, 5, 6]
i=1 key=11 → 11 12 13 5 6 i=2 key=13 → 11 12 13 5 6 i=3 key=5 → 5 11 12 13 6 i=4 key=6 → 5 6 11 12 13 ✔

Best O(n) (sorted data) · average/worst O(n²) · space O(1) · stable ✔ · real libraries isse chhote arrays pe use karti hain

🧠 Yaad rakhne ka tareeka
  • Bubble = paani ke bulbule (bada upar/end me) · Selection = "sabse chhota chuno" · Insertion = taash ke patte
  • Teeno O(n²), teeno in-place (O(1) space)
  • Stable: Bubble ✔, Insertion ✔ · Unstable: Selection ✕
  • Exam me "pass-by-pass table" banane se full marks — sirf program se aadhe milte hain

Merge & Quick Sort — O(n log n)

Divide & conquer · recursion ka asli use

Merge Sort 🔀

Divide & Conquer: array ko aadha-aadha todo (jab tak 1 element bache), phir do sorted halves merge karo. Har case me O(n log n) — guarantee. Isliye jab predictable performance chahiye, merge sort.

/* MERGE SORT — C program */
#include <stdio.h>

/* do sorted halves [l..m] aur [m+1..r] ko merge karta hai */
void merge(int a[], int l, int m, int r) {
    int n1 = m - l + 1, n2 = r - m;
    int L[n1], R[n2], i, j, k;

    for (i = 0; i < n1; i++) L[i] = a[l + i];      // left half copy
    for (j = 0; j < n2; j++) R[j] = a[m + 1 + j];  // right half copy

    i = 0; j = 0; k = l;
    while (i < n1 && j < n2) {                     // dono me se chhota lo
        if (L[i] <= R[j]) a[k++] = L[i++];
        else              a[k++] = R[j++];
    }
    while (i < n1) a[k++] = L[i++];                 // bacha hua left
    while (j < n2) a[k++] = R[j++];                 // bacha hua right
}

void mergeSort(int a[], int l, int r) {
    if (l < r) {                                    // base case
        int m = l + (r - l) / 2;
        mergeSort(a, l, m);                         // left sort
        mergeSort(a, m + 1, r);                     // right sort
        merge(a, l, m, r);                          // dono jodo
    }
}

int main() {
    int a[100], n, i;
    printf("Enter number of elements: ");
    scanf("%d", &n);
    printf("Enter %d elements: ", n);
    for (i = 0; i < n; i++) scanf("%d", &a[i]);

    mergeSort(a, 0, n - 1);

    printf("Sorted array: ");
    for (i = 0; i < n; i++) printf("%d ", a[i]);
    return 0;
}

Quick Sort ⚡

Pivot chuno (last element), partition karo — pivot se chhote left, bade right; pivot apni final jagah pe. Phir dono taraf recursion. Practically sabse fast, par worst case O(n²) (jab array already sorted ho aur pivot last ho).

/* QUICK SORT — C program (pivot = last element) */
#include <stdio.h>

int partition(int a[], int low, int high) {
    int pivot = a[high];          // last element pivot
    int i = low - 1, j, temp;

    for (j = low; j < high; j++) {
        if (a[j] <= pivot) {      // pivot se chhota mila
            i++;
            temp = a[i]; a[i] = a[j]; a[j] = temp;   // left me bhejo
        }
    }
    temp = a[i + 1]; a[i + 1] = a[high]; a[high] = temp; // pivot sahi jagah
    return i + 1;                  // pivot ka index
}

void quickSort(int a[], int low, int high) {
    if (low < high) {
        int pi = partition(a, low, high);
        quickSort(a, low, pi - 1);   // left side
        quickSort(a, pi + 1, high);  // right side
    }
}

int main() {
    int a[100], n, i;
    printf("Enter number of elements: ");
    scanf("%d", &n);
    printf("Enter %d elements: ", n);
    for (i = 0; i < n; i++) scanf("%d", &a[i]);

    quickSort(a, 0, n - 1);

    printf("Sorted array: ");
    for (i = 0; i < n; i++) printf("%d ", a[i]);
    return 0;
}
QUICK SORT — PARTITION KE BAAD PIVOT FINAL JAGAH PE
start: [10, 7, 8, 9, 1, 5] pivot = 5 partition: 1 ≤ 5 mila → 10 ↔ 1 swap [1, 7, 8, 9, 10, 5] pivot ko index 1 pe rakha [1, 5, 8, 9, 10, 7] ← 5 FINAL jagah pe ✔ final: [1, 5, 7, 8, 9, 10] ✔

Best/average O(n log n) · worst O(n²) · space O(log n) · unstable ✕ · qsort() isi pe based hai

🧠 Yaad rakhne ka tareeka
  • Merge = todo phir jodo (predictable, O(n) extra memory) · Quick = pivot se baanto (fast, in-place)
  • Worst case ka fix: random pivot ya median-of-three — exam me likhne se extra marks
  • Dono recursion use karte hain — isliye recursion pehle clear karna zaroori tha

Heap & Radix Sort

In-place guarantee · non-comparison sorting

Heap Sort 🏔️

Array ko max-heap banao (parent ≥ children → sabse bada root pe). Root ko end me bhejo, heap size ghatao, heapify karo — repeat. Do faayde ek saath: in-place (O(1) space) aur har case me O(n log n).

/* HEAP SORT — C program */
#include <stdio.h>

/* node i ko uske subtree me max-heap banao */
void heapify(int a[], int n, int i) {
    int largest = i;
    int l = 2 * i + 1;               // left child
    int r = 2 * i + 2;               // right child
    int temp;

    if (l < n && a[l] > a[largest]) largest = l;
    if (r < n && a[r] > a[largest]) largest = r;

    if (largest != i) {              // child bada nikla
        temp = a[i]; a[i] = a[largest]; a[largest] = temp;
        heapify(a, n, largest);      // neeche bhi theek karo
    }
}

void heapSort(int a[], int n) {
    int i, temp;
    for (i = n / 2 - 1; i >= 0; i--)   // step 1: max-heap banao
        heapify(a, n, i);

    for (i = n - 1; i > 0; i--) {
        temp = a[0]; a[0] = a[i]; a[i] = temp;  // max → end
        heapify(a, i, 0);                      // bache hue ka heap
    }
}

int main() {
    int a[100], n, i;
    printf("Enter number of elements: ");
    scanf("%d", &n);
    printf("Enter %d elements: ", n);
    for (i = 0; i < n; i++) scanf("%d", &a[i]);

    heapSort(a, n);

    printf("Sorted array: ");
    for (i = 0; i < n; i++) printf("%d ", a[i]);
    return 0;
}

Har case O(n log n) · space O(1) · unstable ✕ · priority queue bhi isi heap se banta hai

Radix Sort 🔢

Comparison karta hi nahi! Digit-wise sort: pehle units (LSD), phir tens, phir hundreds. Har pass me stable counting sort. Complexity O(d(n+k)), space O(n+k), stable ✔.

/* RADIX SORT — C program (LSD, base 10) */
#include <stdio.h>

/* exp ke digit pe stable counting sort */
void countingSort(int a[], int n, int exp) {
    int output[n], count[10] = {0}, i;

    for (i = 0; i < n; i++)                     // digit frequency
        count[(a[i] / exp) % 10]++;

    for (i = 1; i < 10; i++)                    // cumulative count
        count[i] += count[i - 1];

    for (i = n - 1; i >= 0; i--) {              // peeche se → stable
        output[count[(a[i] / exp) % 10] - 1] = a[i];
        count[(a[i] / exp) % 10]--;
    }
    for (i = 0; i < n; i++) a[i] = output[i];
}

void radixSort(int a[], int n) {
    int max = a[0], i, exp;
    for (i = 1; i < n; i++)                     // max nikaalo
        if (a[i] > max) max = a[i];

    for (exp = 1; max / exp > 0; exp *= 10)     // units, tens, ...
        countingSort(a, n, exp);
}

int main() {
    int a[100], n, i;
    printf("Enter number of elements: ");
    scanf("%d", &n);
    printf("Enter %d elements: ", n);
    for (i = 0; i < n; i++) scanf("%d", &a[i]);

    radixSort(a, n);

    printf("Sorted array: ");
    for (i = 0; i < n; i++) printf("%d ", a[i]);
    return 0;
}

Har pass stable hai — isliye pichle digit ka order bana rehta hai. Numbers/strings ke liye best, floating point pe seedha nahi chalta.

🧠 Yaad rakhne ka tareeka
  • Heap = tree jaisa dher (bada upar) · Radix = digit ke hisaab se buckets
  • Heap hi ek aisa sort hai jo O(1) space + har case O(n log n) dono deta hai
  • Radix ke liye yaad rakho: LSD pehle (units → tens → hundreds), aur stable hona zaroori

Q&A — expected exam questions

Question kholo, khud likho, phir model answer se milao

Differentiate linear search and binary search. Condition likho. 2 MARKS

Linear: ek-ek karke compare, kisi bhi (unsorted) array pe chalta hai, O(n). Binary: beech se compare karke aadha hissa hata deta hai, sorted array mandatory, O(log n).

What is hashing? What is a collision and how is it resolved? 5 MARKS

Hashing key ko h(k) se table index pe map karta hai → average O(1) search. Collision jab do keys ka same hash value aaye (h(23) = h(33) = 3, m = 10).

Resolution: (1) Chaining — har slot me linked list. (2) Open addressing — table ke andar probing: linear (h+i), quadratic (h+i²), double hashing (h + i·h₂) — best. Deletion me tombstone marker.

Sort 5, 1, 4, 2, 8 using bubble sort — show each pass + write C program. 5 MARKS

Passes: 1 → 1, 4, 2, 5, 8 · 2 → 1, 2, 4, 5, 8 · 3 → 1, 2, 4, 5, 8 (no swap) · 4 → sorted.

Program section 02 ka bubble sort code (n−1 passes, adjacent swap). Complexity: best O(n), avg/worst O(n²), space O(1), stable.

Explain merge sort — algorithm, C program, complexity. Linked list ke liye kyun better? 10 MARKS

Idea: divide & conquer — array ko aadha todo jab tak 1 element bache, phir do sorted halves merge karo (do pointers se chhota pehle uthao). Recurrence: T(n) = 2T(n/2) + O(n) ⇒ O(n log n) har case. Space O(n), stable.

Linked list ke liye: merge wahan O(1) extra space me ho jata hai (pointers rewire) aur random access (a[mid]) ki zaroorat nahi padti — jo linked list me O(n) hota hai.

Explain quick sort with partition. Worst case O(n²) kab hota hai? 10 MARKS

Pivot chuno (last), partition karo — chhote left, bade right; pivot final jagah pe. Phir dono taraf recursion.

Worst case: jab pivot har baar smallest/largest ho — partition 0 aur n−1 me bant jaye (T(n) = T(n−1) + O(n)). Yeh hota hai jab array already sorted ho aur pivot last chuna jaye. Fix: random pivot / median-of-three. Average O(n log n), space O(log n), unstable.

Compare all sorting algorithms (time, space, stability). Best kaunsa, kab? 10 MARKS

Section 06 ka master table poora likho. Stable: bubble, insertion, merge, radix (BIMR).

"Best" situation pe depend karta hai: chhota/nearly-sorted → insertion; general speed → quick; guarantee + stable → merge; memory tight → heap; numbers with few digits → radix. Yeh decision table likhne se answer complete hota hai.

Exam Corner

Verbatim definitions + last-minute 15 one-liners

SEARCHING

Locating a given element (key) in a collection, returning its position or reporting absence.

LINEAR SEARCH

Sequential search comparing the key with each element from the beginning; works on unsorted data; worst case O(n).

BINARY SEARCH

Search on a sorted array that compares the key with the middle element and discards half the remaining elements each step; O(log n).

HASHING

Mapping keys to positions of a hash table using a hash function h(k), giving near-constant-time insertion, deletion and search.

COLLISION

When two different keys produce the same hash value (same table index). Resolved by chaining or open addressing.

CHAINING (OPEN HASHING)

Collision resolution where each table slot maintains a linked list of all keys hashing to that slot; table never becomes full.

OPEN ADDRESSING

Collision resolution storing keys within the table itself by probing alternate slots — linear (h+i), quadratic (h+i²), double hashing (h + i·h₂).

LOAD FACTOR

Ratio α = n/m of stored elements to table size; kept 0.5–0.75 for efficiency. Exceeding 1 requires rehashing.

SORTING

Arranging elements in a particular order (ascending/descending) so they can be searched and processed efficiently.

STABLE SORT

A sorting algorithm that preserves the relative order of equal elements. Bubble, Insertion, Merge, Radix are stable.

IN-PLACE SORT

Uses O(1) extra memory apart from the input — bubble, selection, insertion, heap sort.

DIVIDE & CONQUER

Divide the problem into sub-problems, solve recursively, combine results — used by merge sort and quick sort.

Last-minute 15 one-liners 🎯

  1. Binary search ke liye array sorted hona chahiye — warna linear chalao.
  2. mid = (low + high) / 2 · chhota hai toh low = mid+1, bada hai toh high = mid−1.
  3. Hashing: h(k) = k mod m · average O(1), worst O(n).
  4. h(23) = h(33) = 3 → collision (m = 10).
  5. Chaining = list per slot · open addressing = table ke andar probing.
  6. Linear probing me primary clustering · double hashing sabse best.
  7. Load factor α = n/m, 0.5–0.75 ideal.
  8. Bubble sort me har pass me ek bada element end me settle hota hai.
  9. Selection sort minimum swaps (n−1) karta hai, par har case O(n²).
  10. Insertion sort nearly-sorted pe O(n) — best case.
  11. Merge sort always O(n log n), stable, space O(n).
  12. Quick sort average O(n log n), worst O(n²) (sorted + last pivot).
  13. Heap sort O(1) space + always O(n log n) — dono ek saath sirf isi me.
  14. Radix sort comparison nahi karta — O(d(n+k)), stable.
  15. Stable sorts yaad rakho: BIMR.
