7 Marks · 2026 Q1. What is Hashing? Explain division method to compute the hash function and also explain the collision resolution strategies used in hashing.
AKTU answer copy · page 1 / 3

Ans. Hashing is a technique of storing and retrieving data in which the key is converted directly into an index of an array (called the hash table) with the help of a mathematical function called the hash function h(k). Because the position is calculated instead of searched, hashing performs insertion, deletion and searching in O(1) average time.

Definition: Hashing is the process of mapping a key value into the address of a hash table using a hash function, so that records can be searched without comparing the keys.
1. Basic Terminology
  • Key (k): the value by which a record is identified (roll no., account no., etc.).
  • Hash table: the array of size m in which records are stored (indices 0 to m−1).
  • Hash function h(k): the function that maps a key to an index.
  • Bucket / Slot: one position of the hash table.
  • Collision: when two different keys give the same index.
  • Load factor α = n/m, where n = number of keys stored.
2. Why Hashing is Needed (comparison)

3. Division Method

It is the simplest and most commonly used hash function. The key is divided by the table size and the remainder is taken as the index:

h(k) = k mod m

where m = size of the hash table. It is recommended to choose m as a prime number, because a prime m distributes the keys more uniformly and reduces collisions.

Disadvantage: if m is not prime (e.g. m = 10), many keys give the same remainder, so collisions increase.

4. Collision and its Cause

A collision takes place when two different keys produce the same hash value, i.e. h(k1) = h(k2) for k1 ≠ k2. Since the table has only m slots and the number of possible keys is much larger, collisions cannot be avoided — they can only be resolved.

In open addressing all keys are stored inside the table itself. When the home slot h(k) is occupied, the next slots are examined in a fixed sequence until an empty slot is found.

6. Load Factor and Rehashing

α = n / m (n = number of keys, m = table size). The ideal value is 0.5 to 0.75. When α becomes greater than 1 (or the table becomes full in open addressing), a new larger table is created and all keys are rehashed into it — this process is called rehashing.

8. Conclusion

Hashing gives the fastest searching among all techniques because no comparison is needed. The division method h(k) = k mod m is used to compute the index, and collisions are handled either by chaining (linked list per slot) or by open addressing (linear, quadratic or double probing). A good hash function with a load factor below 0.75 keeps the average search time close to O(1).

7 Marks · 2026 Q2. Explain linear probing and quadratic probing in hashing with examples.
AKTU answer copy · page 1 / 3

Ans. Probing means searching for an empty slot when the home address h(k) of a key is already occupied. Both linear and quadratic probing belong to open addressing, in which all keys are stored inside the hash table itself and no extra linked list is used.

Open Addressing: A collision resolution technique in which the key is stored in some other empty slot of the same table, found by a probe sequence h0(k), h1(k), h2(k) …
1. Linear Probing

In linear probing the table is searched sequentially from the home position until an empty slot is found. Because the search wraps around the end of the table, the modulus is used:

hi(k) = (h(k) + i) mod m ,   i = 0, 1, 2, 3 …

For i = 0 we get the home address; for i = 1 the next slot; and so on. The sequence of slots examined is therefore h, h+1, h+2, h+3 …

3. Primary Clustering (problem of linear probing)

In linear probing, once a group of consecutive slots becomes full, any new key whose home address falls inside this group has to be placed after the group. The group therefore keeps growing. Such a block of consecutive occupied slots is called a cluster, and the problem is called primary clustering.

4. Quadratic Probing

To reduce clustering, the gap between successive probes is increased in quadratic probing. The probe sequence uses the square of i:

hi(k) = (h(k) + i²) mod m ,   i = 0, 1, 2, 3 …

So the slots examined are h, h+1, h+4, h+9, h+16 …

9. Advantages and Disadvantages

Advantages: no extra memory for pointers; simple to implement; good cache locality (linear probing); all data is stored in one array.

Disadvantages: clustering problem; deletion is difficult (a tombstone marker is required, otherwise the probe chain breaks); performance degrades quickly when the table becomes full.

10. Conclusion

Both linear and quadratic probing resolve collisions by storing the key in another empty slot of the same table. Linear probing checks the next slot (h+i) and is simple but suffers from primary clustering. Quadratic probing uses the gaps 1, 4, 9 … (h+i²), which spreads the keys and reduces clustering. Hence quadratic probing gives fewer probes, while linear probing is simpler and more cache friendly.

7 Marks · 2024 Q3. What are the disadvantages of linear probing in hashing? Discuss how quadratic probing can be used to solve some of these problems.
AKTU answer copy · page 1 / 3

Ans. Linear probing is the simplest open addressing technique in which the next slot is checked one by one, using hi(k) = (h(k) + i) mod m. Although it is easy to implement, it suffers from several serious problems.

1. Disadvantages of Linear Probing

(i) Primary clustering: when several consecutive slots become full, they form a block called a cluster. Any key whose home address lies inside this cluster must be placed after the cluster, so the cluster grows longer and longer. This is the biggest drawback of linear probing.

(ii) Increase in number of probes: because of clustering, the average number of slots examined per insertion or search increases rapidly, and the search time no longer remains O(1).

(iii) Difficulty in deletion: an element cannot be deleted by simply making its slot empty, because the probe sequence of the keys placed after it would break and they would become unreachable. A special marker called tombstone (DELETED) has to be stored in that slot.

(iv) Poor performance at high load factor: when α approaches 1, nearly every insertion requires a long search, and the time complexity degrades towards O(n).

(v) Uneven distribution: keys with nearby home addresses always occupy nearby slots, so the table becomes unevenly filled — some parts are crowded while others remain empty.

2. How Quadratic Probing Solves These Problems

In quadratic probing the step size is not constant; it increases as the square of the probe number:

hi(k) = (h(k) + i²) mod m ,   i = 0, 1, 2, 3 …

Therefore the slots examined are h, h+1, h+4, h+9, h+16 … instead of h, h+1, h+2, h+3 …

(i) Clustering is broken: two keys having nearby home positions do not occupy consecutive slots. They are placed far apart, so a long block of occupied slots cannot be formed. Hence primary clustering is removed.

(ii) Fewer probes: because the keys are spread over the table, the average number of probes per operation becomes smaller and the search time stays close to O(1) even at moderate load factors.

(iii) Better distribution: the table is filled more uniformly, so empty slots are available throughout the table rather than only at the end.

It is clear from the table that in linear probing the keys occupy consecutive slots 3, 4, 5, 6 (a cluster), whereas in quadratic probing they are placed at 3, 4, 7, 2 — spread over the whole table.

3. Limitations of Quadratic Probing

Quadratic probing does not solve every problem. It has its own limitations:

  • Secondary clustering: two keys having the same home address follow exactly the same probe sequence, so they still collide again and again.
  • Not all slots are reachable: the probe sequence may repeat before covering the whole table, so an empty slot may exist but remain unreachable. Hence the table should be at most half full and m should be prime.
  • Deletion problem remains: tombstones are still required, exactly as in linear probing.
  • Poor cache locality: because the slots are not consecutive, more memory blocks are touched during a search.

5. Conclusion

Linear probing suffers mainly from primary clustering, which increases the number of probes and degrades performance. Quadratic probing solves this by using gaps of 1, 4, 9 … so that the keys are distributed over the entire table, the clusters break and fewer probes are needed. However, secondary clustering and the deletion problem remain, which are removed by double hashing.

10 Marks · 2020-21 Q5. Explain any three commonly used hash functions with suitable examples.
AKTU answer copy · page 1 / 3

Ans. A hash function is a mathematical function that converts a key into a valid index of the hash table. The quality of a hash table depends completely on the hash function, because a poor function produces many collisions and slows down the search.

Definition: A hash function h(k) maps a key k from the universe of keys U to an index in the range 0 to m−1, i.e. h : U → {0, 1, 2, …, m−1}.
1. Characteristics of a Good Hash Function
  • It should be easy and fast to compute.
  • It should give a uniform distribution of keys over the table.
  • It should minimise collisions.
  • It should use all the digits of the key (so that similar keys do not map to the same slot).
  • It should always return an index in the valid range 0 to m−1.
2. Division Method

In this method the key is divided by the table size and the remainder is taken as the hash value:

h(k) = k mod m

where m is the size of the hash table. The value of m should be a prime number, because if m has many factors then many keys produce the same remainder.

Advantage: very simple and fast. Disadvantage: if the keys have a common pattern (e.g. all end with 0), they all map to the same slot.

3. Mid-Square Method

In this method the key is squared and the middle digits of the result are taken as the index. The number of middle digits taken depends on the size of the table.

h(k) = middle digits of (k²)

Advantage: the middle digits depend on all the digits of the key, so similar keys give different indices and the distribution is good.
Disadvantage: squaring a large key may produce a very long number, so extra care is needed while extracting the middle digits.

4. Folding Method

In this method the key is divided into parts of equal length (except possibly the last part), all the parts are added, and the sum (mod m) is taken as the index.

h(k) = (p₁ + p₂ + p₃ + … ) mod m

Example 1: k = 123456, parts of 2 digits → 12, 34, 56.
Sum = 12 + 34 + 56 = 102 → h(k) = 102 mod 10 = 2.

Example 2: k = 987654321, parts of 3 digits → 987, 654, 321.
Sum = 987 + 654 + 321 = 1962 → h(k) = 1962 mod 10 = 2.

Advantage: it uses every part of the key, so the distribution is uniform. It is especially useful when the key is a long number such as a telephone number or account number.

5. Multiplication Method

In this method the key is multiplied by a constant A (0 < A < 1), the fractional part of the product is taken, and it is multiplied by the table size:

h(k) = ⌊ m × (k·A mod 1) ⌋

A commonly used value is A = 0.6180339887 (the golden ratio). Here m may be any number — it does not have to be prime.

Example: m = 10, k = 45, A = 0.618.

k·A = 45 × 0.618 = 27.81 → fractional part = 0.81
h(45) = ⌊ 10 × 0.81 ⌋ = ⌊ 8.1 ⌋ = 8.

Example: m = 10, k = 23 → 23 × 0.618 = 14.214 → fraction 0.214 → 10 × 0.214 = 2.14 → 2.

Advantage: the table size can be anything and the method gives a very good distribution.
Disadvantage: floating point multiplication is slower than a simple modulus operation.

7. Conclusion

The division method is the most widely used because of its simplicity. The mid-square and folding methods use all the digits of the key and hence give a better distribution for patterned keys. The multiplication method is independent of the table size. In practice, a hash function is chosen so that the keys are distributed uniformly and the load factor stays below 0.75.

  • Number of buckets (table size) m = 10, indices 0 to 9.

  • Performance does not depend on the initial arrangement of data.

Disadvantages:

  • Always O(n²), even if the array is already sorted.
  • Not stable — swapping the minimum with a[i] can change the order of equal elements.
  • Slower than insertion sort for small or nearly sorted arrays.
7. Conclusion

The C program given above sorts 100 integers using selection sort. In every pass the minimum element of the unsorted part is found and swapped with the first element of that part. The total number of comparisons is n(n−1)/2, hence the worst-case time complexity is O(n²) and the space complexity is O(1). It performs the fewest swaps among all the simple sorting algorithms, but it is not stable.

2 Marks · 2024 Q16. How does the choice of pivot element affect the running time of quick sort?
AKTU answer copy · page 1 / 1

Ans. The pivot decides how the array is partitioned. If the pivot divides the array into two nearly equal halves, the recursion depth is log₂n and the time is O(n log n). But if the pivot is always the smallest or the largest element (e.g. the last element of an already sorted array), the partition gives parts of size 0 and n−1, the recursion becomes n, n−1, n−2 …, and the time becomes O(n²). Therefore a random pivot or median-of-three is used to avoid the worst case.
