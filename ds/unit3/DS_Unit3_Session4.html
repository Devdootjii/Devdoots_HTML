Stable vs Unstable — doubt #1

Barabar elements ka order bacha ya nahi — bas itna hi

Definition: Agar do elements barabar hain, toh sort ke baad unka aapas ka order wahi rahe → stable. Order badal jaye → unstable.

DEFINITION — SCREEN PE LIKHO

Stable sort: A sorting algorithm is stable if two elements with equal keys retain their relative order after sorting. Unstable sorts may change the order of equal elements.

KAHAN MATTER KARTA HAI?

Socho students ka data pehle naam se sorted hai. Ab tumhe marks se sort karna hai. Agar sort stable hai → same marks wale students naam ke order me hi rahenge. Unstable me order bigad jayega aur dobara naam se sort karna padega.

KAUN STABLE HAI?

BIMR = Bubble, Insertion, Merge, Radix → stable ✔
Selection, Quick, Heap → unstable ✕

⚡ STABILITY DEMO— barabar elements (3a, 3c) ka order dekho
BUBBLE SORT — STABLE
Chalao aur dekho — 3a pehle, 3c baad me.
SELECTION SORT — UNSTABLE
Chalao aur dekho — 3a aur 3c ka order badal jayega.
Original: (3,a) (1,b) (3,c) (2,d) — barabar keys ke saath letters, taaki order dikhe.
🧠 Yaad rakhne ka tareeka
  • Stable = "barabar wale apni jagah" (order safe)
  • BIMR stable · Selection, Quick, Heap unstable
  • Selection unstable kyun: min ko swap karte waqt ek barabar element aage se peeche chala jata hai
  • Exam me: "Is merge sort stable? Justify" → haan, kyunki merge me <= use karte hain (left wala pehle)

Hashing — saare methods + formulas (doubt #2)

4 hash functions + 4 collision methods — formula ke saath

Hashing me do cheezein hoti hain: (A) hash function (key → seat number) aur (B) collision resolution (seat bhara mile toh kya). Dono ke chaar-chaar tareeke hain — formulas ke saath.

A. Hash functions — 4 tareeke

1. DIVISION METHOD

h(k) = k mod m

Key ko table size se divide karo, remainder hi seat. Sabse simple aur sabse zyada use hone wala. m ko prime rakhna best hota hai.

2. MID-SQUARE METHOD

h(k) = k² ke beech ke r digits

Key ka square karo, usme se beech ke digits uthao. Example: k = 23 → 23² = 529 → beech ka digit 2.

3. FOLDING METHOD

h(k) = (tukdon ka sum) mod m

Key ko tukdon me todo, sab jodo. Example: 123456 → 12 + 34 + 56 = 102 → 102 mod 10 = 2.

4. MULTIPLICATION METHOD

h(k) = ⌊m × (k·A mod 1)⌋

A ≈ 0.618 (golden ratio). Key ko A se multiply karo, fractional part lo, m se multiply karo. Table size koi bhi ho sakta hai.

Yeh table pen se banao — 33 wali line pe circle karo, yahi collision hai.

LOAD FACTOR + REHASHING

α = n/m · ideal 0.5–0.75 · α > 1 (chaining me) ya table full (probing me) → rehashing: nayi badi table banao, sab keys dobara hash karo.

DELETION KA TRAP

Open addressing me element delete karke slot khaali nahi chhod sakte — probe chain toot jayegi. Wahan tombstone (DELETED ka nishaan) lagao.

🧠 Yaad rakhne ka tareeka
  • Hash function: Division (k mod m) · Mid-square (k² ka beech) · Folding (tukde jodo) · Multiplication (m × frac)
  • Collision: Chaining (list) · Linear (i) · Quadratic (i²) · Double (i·h₂)
  • Probings me sab mod m — matlab circular (aakhir ke baad 0 pe wapas)
  • Average O(1), worst O(n) · α 0.75 se neeche

Heap Sort — tree jaisa sort

Max-heap · root pe sabse bada · O(n log n) har case + O(1) space

Analogy — company ka boss. Max-heap me root (index 0) pe sabse bada hota hai, aur har parent apne bachchon se bada. Toh: root ko end me bhej do (wo apni final jagah pe), heap size 1 ghatao, heapify karke phir se bada element root pe lao. Repeat.

DEFINITION — SCREEN PE LIKHO

Heap Sort: Builds a max-heap from the array, repeatedly swaps the root (largest) with the last element, reduces heap size and heapifies. O(n log n) in all cases, O(1) space, unstable.

ARRAY = TREE (koi pointer nahi)

Node i ke bachche: 2i+1 (left) aur 2i+2 (right) · Parent: (i−1)/2
Jaise [10, 5, 3, 4, 1]: index 0 = 10 (root), uske bachche index 1 = 5 aur index 2 = 3.

DO STEP

1. Build max-heap — aakhri parent n/2−1 se 0 tak heapify.
2. Repeat: root ↔ last swap → size ghatao → heapify.

/* ============ HEAPIFY: node i ko uske subtree me max-heap banao ============ */
void heapify(int a[], int n, int i) {
    int largest = i;                     // maan lo parent hi sabse bada hai
    int l = 2 * i + 1;                    // left child ka index
    int r = 2 * i + 2;                    // right child ka index

    if (l < n && a[l] > a[largest])        // left child bada hai? (aur exist karta hai)
        largest = l;                      // → largest = left

    if (r < n && a[r] > a[largest])        // right child usse bhi bada?
        largest = r;                      // → largest = right

    if (largest != i) {                   // koi bachcha parent se bada nikla?
        int t = a[i]; a[i] = a[largest]; a[largest] = t;   // swap parent ↔ child
        heapify(a, n, largest);           // neeche wala hissa bhi theek karo (recursion)
    }
}

/* ============ HEAP SORT ============ */
void heapSort(int a[], int n) {
    for (int i = n / 2 - 1; i >= 0; i--)  // STEP 1: max-heap banao (aakhri parent se)
        heapify(a, n, i);                // → har node ko heapify karo

    for (int i = n - 1; i > 0; i--) {      // STEP 2: bada element end me bhejo
        int t = a[0]; a[0] = a[i]; a[i] = t;  // root (max) ↔ last element
        heapify(a, i, 0);                // → bache hue heap ko phir se theek karo
    }
}
⚡ HEAP SORT STEPPER— heap bante hue aur max end me jate hue
PLAY dabao — pehle max-heap banega, phir max end me jayega.
🧠 Yaad rakhne ka tareeka
  • Heap = array me tree · bachche 2i+1, 2i+2 · parent (i−1)/2
  • Har case O(n log n) + O(1) space — yahi combination sirf isi me hai
  • Unstable ✕ · priority queue bhi heap se banti hai
Exam pointer (10 marks): "Sort [4,10,3,5,1] using heap sort — show heap after each step" + heapify ka code. Heap ka array view banana zaroori hai (tree draw karna optional).

Radix Sort — digit wise

Comparison hi nahi · LSD (units) se shuru · stable hona zaroori

Analogy — roll numbers ka almari. Pehle sabko units digit ke hisaab se 10 dabbon me daalo, phir unhe wapas utha ke tens digit ke hisaab se daalo, phir hundreds ke hisaab se. Aakhir me sab sorted! Comparison ek bhi nahi.

DEFINITION — SCREEN PE LIKHO

Radix Sort: A non-comparison sort that processes digits from least significant (LSD) to most significant, using a stable counting sort for each digit pass. Time O(d(n+k)), space O(n+k), stable.

/* ============ COUNTING SORT: exp ke digit ke hisaab se (stable) ============ */
void countingSort(int a[], int n, int exp) {
    int output[n];                       // naya array (stable rakhne ke liye)
    int count[10] = {0};                  // digits 0..9 ki ginti

    for (int i = 0; i < n; i++)          // har element ka digit nikalo
        count[(a[i] / exp) % 10]++;      // exp=1 → units, exp=10 → tens, exp=100 → hundreds

    for (int i = 1; i < 10; i++)          // cumulative count (position nikalne ke liye)
        count[i] += count[i - 1];        // → count[d] = d tak kitne elements

    for (int i = n - 1; i >= 0; i--) {    // PEECHE se chalo — isliye STABLE rehta hai
        int d = (a[i] / exp) % 10;       // is element ka digit
        output[count[d] - 1] = a[i];     // → uski sahi jagah pe rakho
        count[d]--;                      // → agla same digit ek kadam pehle
    }

    for (int i = 0; i < n; i++)          // output ko wapas a[] me copy karo
        a[i] = output[i];
}

/* ============ RADIX SORT ============ */
void radixSort(int a[], int n) {
    int max = a[0];                       // sabse bada element dhoondho
    for (int i = 1; i < n; i++)          // (uske digits ki ginti chahiye)
        if (a[i] > max) max = a[i];

    for (int exp = 1; max / exp > 0; exp *= 10)  // units → tens → hundreds…
        countingSort(a, n, exp);         // → har digit pe ek stable pass
}
⚡ RADIX PASSES— units → tens → hundreds
STEP dabao — har pass ke baad array dikhega.

COMPLEXITY

O(d × (n + k)) — d = max digits, k = base (10). 3-digit numbers → 3 passes. Space O(n + k). Stable ✔

DHYAN RAKHO

Numbers/strings ke liye best. Floating point pe seedha nahi chalta. Aur LSD (units) se shuru karna zaroori hai — MSD se karoge toh galat hoga.

🧠 Yaad rakhne ka tareeka
  • Radix = digit wise, LSD (units) se shuru
  • Andar stable counting sort — isliye radix bhi stable
  • Comparison nahi karta — isliye O(n log n) wali limit se bach jata hai

Exam Corner — verbatim definitions

Searching

Finding the location of a given element (key) in a collection.

Linear Search

Compares the key with each element one by one from the beginning; works on unsorted data. O(n).

Binary Search

Repeatedly compares the key with the middle element of a sorted array and halves the search space. O(log n).

Hashing

Mapping keys to table positions using a hash function h(k) for near-constant-time search.

Collision

When two different keys map to the same hash value/index.

Load Factor

α = n/m — number of elements stored divided by table size; ideal 0.5–0.75.

Sorting

Arranging elements in a particular order (ascending/descending).

Stable Sort

Equal keys retain their relative order after sorting.

In-place

Sorting that uses O(1) extra memory (only a few variables).

Divide & Conquer

Divide the problem into sub-problems, solve recursively, then combine (merge/quick sort).

Max-Heap

A complete binary tree where every parent is ≥ its children; stored in an array with children at 2i+1, 2i+2.

Radix Sort

Non-comparison sort processing digits from least significant to most significant using stable counting sort.

⚡ 15 last-minute one-liners
  • Binary search ke liye sorted array compulsory
  • Linear best O(1), worst O(n)
  • Binary: 1000 elements me ~10 steps
  • Hashing average O(1), worst O(n)
  • h(k) = k mod m (division method)
  • Collision = same hash value — hamesha possible
  • Chaining = list · Probing = agli khaali seat
  • α = n/m, 0.75 se neeche rakho
  • Bubble: n−1 passes, stable
  • Selection: minimum swaps, unstable, har case O(n²)
  • Insertion: best O(n), stable, shift karta hai
  • Merge: har case O(n log n), stable, O(n) space
  • Quick: worst O(n²) (sorted + last pivot), in-place
  • Heap: O(n log n) + O(1) space, unstable
  • Radix: comparison nahi, stable, LSD se shuru
